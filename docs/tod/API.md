# Models

Models are defined in `darehouse.tod.models`.

## Player

```python
@dataclass
class Player:
    id: int
```

Represents a player participating in a Truth or Dare game.

### Attributes

| Attribute | Type | Description |
|---|---|---|
| `id` | `int` | Identifier assigned to the player by the integrating application |

Player identifiers are not managed or generated by the engine. The integrating application is responsible for assigning and maintaining player IDs.

---

## Prompt

```python
@dataclass
class Prompt:
    content: str
    type: PromptType
```

Represents a Truth or Dare prompt.

### Attributes

| Attribute | Type | Description |
|---|---|---|
| `content` | `str` | The text of the prompt |
| `type` | `PromptType` | The category of the prompt |

---

## PromptType

```python
class PromptType(Enum):
    TRUTH = "truth"
    DARE = "dare"
```

Enumeration representing the available prompt categories.

### Members

| Member | Value | Description |
|---|---|---|
| `PromptType.TRUTH` | `"truth"` | A truth prompt |
| `PromptType.DARE` | `"dare"` | A dare prompt |

---

## GameState

```python
@dataclass
class GameState:
    players: list[Player]
    last_prompts: list[Prompt]
    current_player_index: int
    is_running: bool
```

Represents the state of a lobby or active game.

### Attributes

| Attribute | Type | Description |
|---|---|---|
| `players` | `list[Player]` | Players currently in the lobby or game |
| `last_prompts` | `list[Prompt]` | Recently generated prompts retained by the engine |
| `current_player_index` | `int` | Index of the current player in `players` |
| `is_running` | `bool` | Whether the game is currently running |

A `GameState` instance is created internally when a lobby is created.

The game state is accessible through `TODEngine.game`.

# Protocols

Protocols are defined in `darehouse.tod.protocols`.

## PromptProvider

```python
class PromptProvider(Protocol):
    def get_prompt(self, prompt_type: PromptType) -> Prompt:
        ...
```

Protocol defining the interface required by a prompt provider.

Implementations are responsible for generating and returning a prompt corresponding to the requested type.

### Methods

#### `get_prompt(prompt_type)`

Generates and returns a prompt of the requested type.

| Parameter | Type | Description |
|---|---|---|
| `prompt_type` | `PromptType` | The category of prompt to generate |

**Returns:** `Prompt`

Implementations must return a `Prompt` instance corresponding to the requested prompt type.

The engine does not implement prompt generation itself.

# Engine

The engine is defined in `darehouse.tod.engine`.

## TODEngine

```python
class TODEngine:
    ...
```

The Truth or Dare game engine.

Manages lobby creation, player management, game state, turn progression, and prompt history.

Prompt generation is delegated to the configured `PromptProvider`.

Each `TODEngine` instance manages its own game state.

---

## Initialization

### `TODEngine(prompt_provider, maximum_prompts_to_keep)`

Initializes a new Truth or Dare engine.

```python
engine = TODEngine(
    prompt_provider=my_prompt_provider,
    maximum_prompts_to_keep=10,
)
```

### Parameters

| Parameter | Type | Description |
|---|---|---|
| `prompt_provider` | `PromptProvider` | Provider responsible for generating prompts |
| `maximum_prompts_to_keep` | `int` | Maximum number of prompts retained in history |

### Attributes

| Attribute | Type | Description |
|---|---|---|
| `prompt_provider` | `PromptProvider` | Configured prompt provider |
| `maximum_prompts_to_keep` | `int` | Configured prompt history limit |
| `game` | `GameState \| None` | Current game state, or `None` if no lobby exists |

### Raises

- `ValueError` — If `maximum_prompts_to_keep` is negative.

A value of `0` disables prompt history retention.

# Lobby Management

## `create_lobby()`

```python
engine.create_lobby()
```

Creates a new lobby and initializes its game state.

The newly created lobby contains no players and is not running.

### Returns

`None`

### Raises

- `GameAlreadyExists` — If a lobby already exists.

---

## `check_game()`

```python
engine.check_game()
```

Checks whether a game state currently exists.

This method is primarily intended for internal engine operations.

### Returns

`None`

### Raises

- `GameDoesNotExist` — If no lobby or game state exists.

---

# Player Management

## `add_player(player)`

```python
engine.add_player(player)
```

Adds a player to the current lobby.

Players may be added before or during a running game.

### Parameters

| Parameter | Type | Description |
|---|---|---|
| `player` | `Player` | Player to add |

### Returns

`None`

### Raises

- `GameDoesNotExist` — If no lobby exists.
- `PlayerAlreadyExists` — If the player is already present.

---

## `remove_player(player)`

```python
engine.remove_player(player)
```

Removes a player from the current lobby.

Players may be removed before or during a running game.

### Parameters

| Parameter | Type | Description |
|---|---|---|
| `player` | `Player` | Player to remove |

### Returns

`None`

### Raises

- `GameDoesNotExist` — If no lobby exists.
- `PlayerDoesNotExist` — If the player is not present.

# Game Lifecycle

## `start_game()`

```python
engine.start_game()
```

Starts the current game.

The player order is shuffled before the game begins.

### Returns

`None`

### Raises

- `GameDoesNotExist` — If no lobby exists.
- `InsufficientPlayers` — If the lobby contains no players.
- `GameAlreadyRunning` — If the game is already running.

---

## `end_game()`

```python
engine.end_game()
```

Ends the current game and removes its game state from the engine.

After calling this method, `engine.game` becomes `None`.

A new lobby may subsequently be created using `create_lobby()`.

### Returns

`None`

### Raises

- `GameDoesNotExist` — If no lobby exists.

---

# Turn Management

## `advance_turn()`

```python
engine.advance_turn()
```

Advances the current player index to the next player.

When the end of the player list is reached, the index wraps around to the beginning.

### Returns

`None`

### Raises

- `GameDoesNotExist` — If no lobby exists.
- `GameNotRunning` — If the game is not running.
- `InsufficientPlayers` — If no remain in the lobby.

### Behavior

Given the following player order:

```text
Player 1 -> Player 2 -> Player 3 -> Player 1
```

Calling `advance_turn()` moves the current player to the next index in the list.

The player order may change if players are added or removed during gameplay.

# Prompt Management

## `get_prompt(prompt_type)`

```python
prompt = engine.get_prompt(PromptType.TRUTH)
```

Requests a prompt from the configured prompt provider.

The returned prompt is appended to the game's prompt history, subject to the configured history limit.

### Parameters

| Parameter | Type | Description |
|---|---|---|
| `prompt_type` | `PromptType` | Type of prompt to request |

### Returns

`Prompt`

The prompt returned by the configured provider.

### Raises

- `GameDoesNotExist` — If no lobby exists.

### Behavior

1. Checks that a game state exists.
2. Requests a prompt from the configured provider.
3. Appends the returned prompt to `game.last_prompts`.
4. Removes the oldest prompt if the history exceeds the configured limit.
5. Returns the generated prompt.

Prompt generation is not restricted to a running game. A prompt may be requested as long as a lobby exists.

# Exceptions

The engine defines the following custom exceptions:

| Exception | Description |
|---|---|
| `GameDoesNotExist` | No game or lobby exists |
| `GameAlreadyExists` | A lobby already exists |
| `GameAlreadyRunning` | The game is already running |
| `GameNotRunning` | The game is not running |
| `PlayerAlreadyExists` | The player is already in the lobby |
| `PlayerDoesNotExist` | The player is not in the lobby |
| `InsufficientPlayers` | The required player count is not met |

For detailed descriptions and handling examples, refer to [`EXCEPTIONS.md`](EXCEPTIONS.md).

---

# Additional Notes

- The engine does not manage player identity beyond the provided player IDs.
- The engine does not persist game state.
- The engine does not provide a user interface.
- The engine does not manage Discord interactions.
- Prompt generation is delegated to the configured prompt provider.
- Game state is accessible through the `game` attribute.
- Players may be added or removed during a running game.
- The engine currently does not provide built-in concurrency management.
